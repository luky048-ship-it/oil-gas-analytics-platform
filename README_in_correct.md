# Отчет об изменениях в ETL-пайплайнах и схемах данных

В ходе выполнения задачи была проведена полная синхронизация документации, SQL-схем инициализации и кода DAG-ов. Все изменения направлены на обеспечение строгой согласованности I/O и соответствие Medallion-архитектуре.

## Ключевые изменения

### 1. Синхронизация с SQL-эталоном
- **Документация:** Файлы `docs/Shema_Cantracts.md` и `docs/Data_Dictionary.md` полностью переписаны на основе фактических DDL-скриптов из `init-sql/`. Теперь они отражают реальные типы (`numeric`, `timestamp`) и ограничения Nullable, принятые в базе данных.
- **Новые таблицы инициализации:**
  - `init-sql/12_missing_metadata.sql`: Созданы таблицы для вотермарок, детальных отчетов DQ и реестра карантина.
  - `init-sql/13_staging_tables.sql`: Созданы staging-таблицы для реализации механизма атомарного свопа данных в Gold-слое.

### 2. Согласование архитектуры и путей (I/O)
- **Унификация слоев:** Пути во всех пайплайнах приведены к стандарту:
  - **Bronze (Raw):** `s3://datalake/raw/` (вместо некорректного `bronze/`).
  - **Silver:** `s3://datalake/silver/`.
- **Partition Discovery:** Исправлена логика `discover_incremental_partitions` для корректной обработки как партиционированных фактов (`partition_date=YYYY-MM-DD`), так и справочников (`wells`, `pumps`).

### 3. Приведение кода к Контрактам
- **Типы данных:** Схемы в пайплайнах Silver и DQ (`config.py`) синхронизированы с SQL. Типы Polars заменены на экземпляры классов (например, `pl.Int32()`) для корректной работы `.cast()`.
- **Timestamp Precision:** Реализовано жесткое требование к точности в 1 секунду (`timestamp(s)`) через логику: `pl.Datetime("ms")` + `.dt.truncate("1s")`.

### 4. Восстановление промышленной логики
- Удалены все временные упрощения (заглушки).
- **Loading DAG:** Восстановлена потоковая загрузка из Postgres через серверный курсор (`itersize=100,000`).
- **DQ Pipeline:** Интегрированы все 7 уровней валидации. `execute_dq_pipeline` теперь вызывает специализированные валидаторы для проверки бизнес-логики, ссылочной целостности и статистического дрейфа.
- **Metadata Management:** Восстановлены реальные вызовы `PostgresHook` для управления распределенными блокировками и вотермарками.

## Выявленные и устраненные расхождения
- В `Data_Dictionary.md` ранее упоминались поля `latitude/longitude` для скважин, которых нет в SQL-схеме — документация приведена в соответствие с SQL.
- Исправлены несоответствия типов `numeric` (ранее `float`) для финансовых и объемных показателей.

## Итоговая проверка
- Код полностью соответствует архитектуре в `README.md` и спецификациям в `/docs`.
- I/O согласован между всеми DAG.
- Синтаксис проверен на Python 3.12.
